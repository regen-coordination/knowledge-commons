# Regen Knowledge Commons — mission & scope (Phase 3 synthesis)

2026-08-31 — provenance in [`extraction.md`](./extraction.md)). Every claim

## Mission

Shared knowledge infrastructure for regenerative coordination. The Toolkit
helps people find, understand, connect, compare, use, document, review, and
improve knowledge across GreenPill, ReFi DAO, Bloom Network, Ethereum public
goods, local nodes, civic infrastructure, ecological stewardship, knowledge
commons, and adjacent regenerative coordination ecosystems (28765–28777).

Public one-liner: *"helps regenerative communities organize scattered
knowledge into a living commons that people can use to orient, connect,
build, document, review, and learn together"* (28777).

## Core diagnosis

Regenerative coordination does not fail only for lack of intention, resources,
or tools — it fails because **knowledge does not coordinate well enough**.
Useful knowledge exists but is hard to find, verify, reuse, and connect to
action. The Toolkit reduces this *knowledge coordination friction* without
becoming the center of the ecosystem (28779–28787).

## Theory of change (condensed, 29061–29087)

Not "we build a toolkit, therefore people benefit", but: reduce knowledge
coordination friction → people move from confusion to clarity → from clarity
to meaningful action → from action to shared learning — via a source-aware,
review-aware, context-aware, implementation-aware knowledge commons.

**Regeneration claim boundary (29089):** the Toolkit does not directly
regenerate ecosystems or communities. It supports the knowledge,
coordination, review, and learning conditions under which regenerative work
becomes more legible, responsible, connected, and field-informed.

## Scope & non-claims

- A **federated knowledge commons**, not one central garden or platform.
- Inclusion ≠ endorsement — resources are captured broadly, distinguished by
  review state, maturity, and public-use boundaries (28791–28797).
- Ethereum/web3 is a substrate and culture, not the whole purpose.
- CSIS-**informed**, not CSIS-conformant; Octo/BKC is an alignment candidate,
  not an adopted ontology.
- AI-assisted but human-governed: AI can synthesize, route, classify; it must
  not silently decide what the commons means.
- Source systems are living knowledge environments — peers, not link pools.

## Who it is for (28993–28997)

Newcomers through high-context contributors: organizers, researchers,
facilitators, funders, storytellers, builders, community weavers, source-system
stewards, organizational maintainers.

## The operating model

- **Kernel (5 objects):** Resource (found) · Concept (explained) · Option
  (reusable) · Deployment (specified) · Signal (learned).
- **Movement:** Discover → Understand → Connect → Compose → Specify →
  Implement → Learn → Evolve.
- **Layers (10):** Ontology & Semantic Kernel · Encyclopedia · Resource Graph
  & Ecosystem Atlas · Concept & Idea Ecology · Option Library · Deployment &
  Structural Integrity · Tracks · Implementation & Learning Memory ·
  Evolution · Infrastructure & Substrate.
- **Non-negotiable distinctions:** option≠deployment, track≠deployment,
  deployment≠implementation, implementation≠pattern, signal≠conclusion,
  type≠tag, claim≠evidence, AI-assisted≠human-reviewed.
- **Minimum ontology rule:** add a type only when it changes routing,
  relationships, review needs, templates, permissions, deployment logic, or
  interface behavior.

## First practical test (29195)

Can a real person bring their context to the Toolkit and leave with more
clarity, useful resources, relevant people, and a meaningful next step?

## Where this repo fits (owner-settled, 2026-08-29)

- **Geo is the canonical data governance layer** for the project's core
  knowledge graph structure; GRC-20 is the ID convention.
- The Geo space `bd727a6a…` (testnet, DAO space) is the **Knowledge
  Commons**: it defines the common ontology — core types, properties, and
  relations — that other aligned spaces extend and populate with their
  knowledge artifacts. It is **foundational, not comprehensive**: it will not
  hold large amounts of content.
- The Resource Graph's canonical home is Geo. The open question is the
  reverse of the master doc's framing: *how should the Resource Graph migrate
  from Geo into Markdown, CSV, JSON, a graph database, or another substrate?*
  This repo (regen/commons) will be used to answer that — future work, out of
  scope for the current branch, which lays the Geo foundation for it.
- `ontology.md` here tracks the Knowledge Commons space's live ontology
  baseline (the space is the source of truth).
