# Regen Knowledge Commons object reviews

Each current Markdown review file contains exactly one Article, Source or Claim. Each file includes its content, relevant uncertainties, evidence references, machine Integrity ratings, human-review checklist and object revision. The Source's unassessed dimensions stay unassessed; the Article's score is never copied onto Claims.

One ingestion produces one draft PR with the complete file set. For the two saved real runs this means seven Markdown files each: one Article, one Source and five Claims. Reviewers can open and comment on each file separately. Two approvals still apply to the exact PR head and complete review scope; separate files do not change the knowledge-promotion policy.

## Reformat and export

Start the local Worker with the existing pilot configuration and a GitHub delivery credential. For a saved completed run:

```sh
bun --env-file=packages/agent/.env.pilot scripts/review.ts <run-id>
bun --env-file=packages/agent/.env.pilot scripts/review.ts <run-id> --status
bun --env-file=packages/agent/.env.pilot scripts/review.ts <run-id> --export
```

The first command dispatches the object-file generation; subsequent calls reuse it. A completed saved assessment is reused without spending. Export writes descriptive filenames under `reports/ingestion/objects/<run-id>-<manifest-digest>/`. No grouped report or index Markdown file is added to that folder. File names include object IDs to distinguish similarly named objects.

`GET /v1/ingestions/:runId/review/report` returns the authenticated edition with `files` and `filesDigest`. Each file has `name`, `objectId`, `markdown` and `markdownDigest`. The legacy `markdown`/`markdownDigest` fields remain in private API artifacts for compatibility. The original ingestion-report endpoint and `report:export` command remain available for historical audit; use `review --export` for current review files.

All files are digest-checked on retrieval, export, GitHub delivery and approval readback. Changing one file changes the manifest and reviewed revision. Older grouped reports and prior PR identities are retained; no evidence or assessment is regenerated by a presentation update. The exact candidate remains unratified and unapproved.

Current exports also check the destination directory's membership. Unexpected files, directories or symbolic links produce `Object report directory membership mismatch`; inspect and move unrelated entries yourself before retrying. The exporter preserves them and can resume a valid partial export. New filenames use the same contact/address redaction as report text. See the [recovery and provenance correction](../architecture/0007-review-recovery-and-extraction-provenance.md) for compatibility details.
